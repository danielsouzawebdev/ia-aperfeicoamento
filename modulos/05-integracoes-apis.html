💡 Analogia: API como garçom

Você não entra na cozinha para preparar o pedido. Você entrega uma solicitação ao garçom, ele conversa com a cozinha e traz uma resposta. Em software, uma API define como um sistema solicita dados ou ações a outro.

1. Vocabulário mínimo

EndpointEndereço de uma função/recurso da API.
GETNormalmente busca dados.
POSTNormalmente envia/cria dados.
JSONFormato comum de troca de dados estruturados.
WebhookUma URL que recebe uma notificação quando um evento acontece.
AutenticaçãoForma de provar que o cliente tem permissão para usar o serviço.
Status HTTPIndica resultado da requisição: sucesso, erro de cliente, erro de servidor etc.

2. Leia este JSON

{ "cliente": "Marina", "categoria": "LEAD_QUENTE", "pedido": "assinatura mensal", "valor_estimado": 189.90 }

Um workflow pode ler categoria e decidir: se for LEAD_QUENTE, priorizar atendimento.

3. Status HTTP como pista de diagnóstico

2xxA requisição foi processada com sucesso.
400O cliente enviou algo inválido: JSON, campo ou formato.
401 / 403Problema de autenticação ou autorização.
404Endpoint/recurso não encontrado.
429Limite de requisições excedido; pode exigir espera/retry.
5xxFalha do serviço remoto; trate como indisponibilidade.

4. Idempotência e duplicidade

Imagine que o workflow envia um pedido, perde a conexão e tenta novamente. Se a operação criar outro pedido, você terá duplicidade. Em processos críticos, pergunte: “Se esta etapa rodar duas vezes, o resultado continua correto?”

💡 Nem todo processo precisa implementar idempotência tecnicamente no curso de iniciação de APIs, mas o aluno deve reconhecer o risco de repetir ações como cobrança, cadastro e envio de mensagem.

5. JSON válido não significa dado válido

Sintaticamente válido

{"categoria":"LEAD_QUENTE","score":999}

Semanticamente suspeito

O JSON pode estar perfeito, mas o score 999 pode violar a regra de 0 a 100.

Por isso aplicações devem validar estrutura + valores + regras de negócio.

🔎 API é contrato de comunicação

Mais importante do que decorar métodos HTTP é entender que dois sistemas precisam concordar sobre endereço, autenticação, formato da entrada, formato da saída e significado dos erros.

EndpointOnde a operação está disponível.
AutenticaçãoComo o serviço verifica quem está chamando.
SchemaQuais campos e tipos de dados são esperados.
StatusUma pista sobre o resultado da requisição.
LimitesRate limit, paginação, tamanho, timeout e outras restrições operacionais.
